# 质量层跨解析器基线

- 阶段：P0 基线与回归护栏
- 记录日期：2026-08-25
- 质量层输入：ParsedDocument 2.2
- 原则：按文档携带的表示和证据评估，不按 parser_id 分支修复

新增的 p0-markitdown fixture 由当前虚拟环境中实际可用的 MarkItDown adapter 生成，不是手工伪造的 ParsedDocument。

自动化护栏位于 tests/quality/contract/test_parser_agnostic_baseline.py，包含：

- 每个归档 fixture 都能独立通过质量流水线；
- 质量流水线不得改写输入 fixture；
- optimized markdown、canonical document 的哈希必须与 package manifest 一致；
- 仅一个行尾空格不得残留；两个及以上空格和制表符保留，以免破坏 Markdown 硬换行或代码语义；
- 解析器族、表格表示和能力状态变化必须显式更新基线。

## 当前样本缺口

前端可选但尚无真实质量 fixture 的解析器族：

- ocr：当前环境的 OCR adapter 注册为不可用；
- anydoc：当前环境没有 AnyDoc executable。

这两类输出不得被伪造为“真实解析器质量结果”。当环境就绪后，应采集脱敏原生产物，加入 parsed_documents，再更新自动基线。

## 已识别的数据差异

MinerU archived fixture 中，部分文档声明 ocr_confidence 为 available，但 ocr_spans 数量为 0。该差异已由基线显式记录，不作为质量层的已验证 OCR 证据使用。

P2 的 RepresentationInventory 将把“能力声明”和“具体表示对象”同时建模；届时应将这种差异升级为可解释的 partial 或 unavailable，而不是让单一 capability 状态代表不存在的 span 证据。

## 与后续阶段的关系

- P1 已修复 QL-RPR-001 对 Markdown 硬换行的误删问题；
- P0 以本基线为后续表示清单和表格解析器的回归护栏；
- P2 才引入精确修复目标和 RepresentationInventory；
- P3 才把 HTML、Markdown、cells 的表格选择逻辑集中到 TableRepresentationResolver；
- P4 才迁移到 RepairProposal、Policy、Executor、Verifier 模型。
