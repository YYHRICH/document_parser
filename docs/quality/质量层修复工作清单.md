# 质量层当前修复工作清单

> 状态：P0～P5 已完成  
> 范围：仅 `quality/` 的确定性修复；不调用 Agent、LLM、解析器或外部服务。

## 修复原则

原始 `ParsedDocument` 永远只读。质量层对内部工作文档提出和执行精确补丁；每条补丁必须携带修复目标、执行前 SHA-256、来源证据、策略决定和复检结论。

```text
RepresentationInventory
  → RepairProposal
  → RepairPolicy
  → RepairExecutor
  → RepairVerifier
  → optimized_markdown / CanonicalDocument / QualityReport
```

只有 `auto_safe` 且前置条件匹配的提案可自动执行。任何 `review_required`、`forbidden`、哈希不匹配或复检仍会改变内容的提案都不会改动工作文档，并在审计中保留原因。

## 已注册修复

| 规则 | 目标 | 行为 | 自动执行边界 |
| --- | --- | --- | --- |
| `QL-RPR-001` | document/block Markdown | 清理可证明非语义的行尾空白 | 保留 Markdown 硬换行、Tab、围栏代码和原换行符 |
| `QL-RPR-002` | document/block Markdown | 对齐 Markdown 表格分隔行 | 仅改分隔行，不改表头、数据、公式或代码围栏 |
| `QL-RPR-003` | 包含指定表格 HTML 的 document/block Markdown | `table_html_to_markdown` | 必须由表格表示解析器判为无 span、结构一致且来源 HTML 在目标中只出现一次 |

## QL-RPR-003 的表格策略

表格修复不再按 MinerU 或其他解析器名称判断。质量层比较 `ParsedTable.html`、`ParsedTable.markdown` 和 `ParsedTable.cells`：

- 无合并单元格且结构完整：生成 `auto_safe` 提案；
- 已有一致的无 span Markdown：采用该 Markdown 作为安全展示结果；
- `rowspan/colspan`：保留 HTML/cells，默认不自动覆盖；
- 表示冲突、HTML 不完整、cells 不可信或 HTML 在修改目标中重复：不提出自动修复。

每个表格修复的参数都包含 `table_id`、来源表格表示目标、来源哈希和决策类型；实际写入目标是对应的 document 或 block Markdown 字段。

## 审计、重放与回滚

`QualityReport.applied_repairs` 中的每条记录都包括：

- 稳定 `repair_id`、规则 ID 和受影响 block；
- `target`：object type、ID、field path、occurrence 与稳定键；
- `precondition`：修改前与预期修改后 SHA-256；
- `policy`：自动执行授权原因；
- `verification`：重新运行相同修复规则后的 no-op 结论；
- `before/after`、参数、证据引用和安全回滚数据。

相同输入与配置重复运行会得到相同的修复 ID、顺序和哈希。回滚只在当前内容严格等于记录的 `after` 时允许。

## 明确禁止

不自动猜测 OCR 字符，不改写句子，不补数字、公式、标题、表头或单元格，不推断缺失值，不伪造 bbox/页码/来源，也不盲目合并跨页表格。
