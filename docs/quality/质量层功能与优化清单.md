# 质量层功能与优化清单

> 状态：P0～P5 已完成  
> 范围：`quality/`、`tests/quality/` 以及质量输入/输出边界。  
> 不在范围：路由、解析器、后端、前端、Agent/LLM 与自动重新解析。

## 当前边界

质量层只接收已校验的 `ParsedDocument 2.2`，输出兼容的 `QualityPackage 1.0`。原始输入保持只读；质量层不会按 `parser_id` 选择规则、修复策略或表格处理逻辑。

唯一的共享依赖是 `quality.contracts → core/contracts.py`。本轮未升级公开协议，也没有改变前端、API、解析器或存储契约。

## 当前流水线

```text
ParsedDocument
  → EvidenceContext + RepresentationInventory
  → RepairProposal → Policy → Executor → Verifier
  → 内部工作文档
  → QualityRule + CapabilityMatrix + Gate
  → CanonicalDocument + QualityReport + PackageManifest
  → QualityPackage
```

- `RepresentationInventory` 枚举 document/block Markdown、table HTML/Markdown/cells、OCR spans、assets 与 native artifacts；
- 实际对象状态会覆盖错误的 capability 声明：空 OCR spans 或空 table cells 不能被声明的 available 放行；
- 修复使用目标和 SHA-256 前置条件；内容过期、策略拒绝或复检失败时不修改工作文档；
- canonical、optimized Markdown、规则复检和修复报告使用同一内部工作文档。

## 已实现能力

- 完整性、来源、标题、引用、表格字段绑定与跨页表格规则；
- 证据可用性、适用性、能力矩阵和 Gate；
- QL-RPR-001 安全行尾空白规范化；
- QL-RPR-002 Markdown 表格分隔行对齐；
- QL-RPR-003 解析器无关的 HTML 表格 Markdown 转换；
- 表格 HTML、Markdown、cells 的结构比对、差异审计和 span 有损保护；
- 稳定 ID、确定性输出、质量包哈希和原子写入/校验；
- `python -m quality` 独立调试与 `--show-repairs` 审计输出。

## 表格自动修复准入

| 表格证据状态 | 处理 |
| --- | --- |
| 完整且无 span 的 HTML；或与 cells/Markdown 一致 | 可生成 auto_safe 表格修复提案 |
| 有 rowspan/colspan | 保留结构事实，默认人工复核，不自动用 Markdown 覆盖 |
| HTML、Markdown、cells 不一致 | 不选择任一表示，不自动修改 |
| HTML 在目标 Markdown 中不存在或出现多次 | 拒绝精确执行并记录审计 |
| 缺表格 | 表格规则 not_applicable，不阻塞 Gate |

## 兼容性与可观测性

`QualityPackage 1.0` 保持可读。修复审计扩展在既有 `AppliedRepair.evidence` 和 `QualityReport.metrics` 中，旧消费者仍可读取原字段。

`--show-repairs` 输出提案、策略、执行、验证和表格决策；`--json` 仍输出完整 QualityPackage。

## 不自动修复的内容

OCR 猜字、错别字纠正、断词通用拼接、标题/引用/页码/bbox 伪造、数值或公式补全、单元格补写、跨页表强制合并，以及任何依赖外部知识改变原文的操作都被禁止。
