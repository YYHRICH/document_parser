# 详细仓库实现方案

## 1. 本次 MVP 目标

本次实现把前期部署和实测结论转成可运行路由。解析器范围冻结为：

- AnyDoc：旧 Office 直读、现代 Office 回退；
- Docling：本地通用解析，扫描件和图片通过 RapidOCR；
- MinerU：云端精准解析，PDF 固定主路由，质量优先模式的图片主路由；
- passthrough：项目内置的 Markdown/TXT 原文直通，不是外部模型。

路由输入为 `DocumentSignals`，输出为已有的 `RoutingDecision 1.0`。本分支不执行
第三方解析器，不改变 `ParsedDocument 2.2` 和 `QualityPackage 1.0` 的字段语义。

## 2. 总体结构

```text
ParseRequest
  -> SimpleSourceInspector
  -> ModelRouter
     -> RoutingSettings
     -> CapabilityRegistry
     -> local_first / quality_first policy
  -> RoutingDecision 1.0
  -> Gateway（朱对接）
  -> AnyDoc / Docling / MinerU Adapter（朱实现）
  -> ParsedDocument 2.2
  -> 质量层（叶实现）
```

路由层只回答“本次应该执行哪个解析器、备用顺序和参数是什么”。实际成功解析器必须写入
`ParsedDocument.provenance.parser_id`，不能用计划模型覆盖真实执行模型。

## 3. 模块设计

| 文件 | 作用 |
|---|---|
| `routing/config.py` | 双策略、云端开关、可执行文件和 Token 配置 |
| `routing/registry.py` | 稳定 parser ID、支持格式、运行条件和可用原因 |
| `routing/policy.py` | 纯后缀路由表，不依赖模型私有对象 |
| `routing/router.py` | 自动、手动、fallback 和重解析决策 |
| `routing/errors.py` | 不支持、不可用、禁止云端等可观察异常 |
| `routing/cli.py` | 不启动 Web 的独立调试入口 |
| `datasets/.../routing.jsonl` | 共享 12 文件的固定路由期望 |

## 4. 路由规则

### 4.1 两种模式共同规则

- PDF：允许云端时固定 MinerU，回退 Docling；禁止云端时直接选 Docling。
- DOCX/PPTX/XLSX：Docling，回退 AnyDoc。
- DOC/PPT/XLS：LibreOffice 可用时转新版后 Docling，再回退 AnyDoc；否则 AnyDoc。
- HTML/AsciiDoc/EML/EPUB：Docling。
- Markdown/TXT：UTF-8 原文直通，回退 Docling。
- CSV：保留原 CSV，Docling 生成检索文本，回退 AnyDoc。
- 未验证格式：明确拒绝，不随机尝试解析器。

### 4.2 local_first

BMP、JPG/JPEG、PNG、TIFF、WEBP 均走本地 Docling + RapidOCR。该模式减少云端依赖，
但 PDF 仍遵循本次明确决策优先 MinerU。

### 4.3 quality_first

BMP、JPG/JPEG、PNG、WEBP 优先 MinerU，Docling 回退。TIFF 先无损转 PNG 再提交
MinerU，失败或禁止云端时使用原 TIFF 走 Docling。现代 Office 和 CSV 在
`parser_options.comparison_parser_ids` 中声明 AnyDoc 对比路径，由编排层决定是否执行
双解析；路由层不自动合并内容。

## 5. Adapter 参数

Docling 决策固定声明：Markdown + JSON、referenced 图片、accurate 表格模式。图片、无
文本层 PDF 或扫描比例大于 0 时启用 RapidOCR full-page；其他文件避免无意义整页 OCR。

MinerU 决策固定使用精准 API 和完整 Zip，默认 VLM、表格与公式开启。Adapter 必须下载
并归档 `full.md`、`content_list.json`、`middle.json`、`model.json` 和图片。Token 不进入
决策对象。

AnyDoc 输出 Markdown，并保留源文件作为结构和数值回溯依据。

## 6. 统一产物

```text
task-result/
├─ document.md
├─ images/
├─ parsed_document.json
├─ native/
│  └─ <parser_id>/
├─ routing_decision.json
├─ quality/
└─ task.json
```

`document.md + images/` 是展示交付，`parsed_document.json` 是下游公共主数据，
`native/` 是不可伪造的解析器证据。Adapter 可以复制、重命名图片并改写 Markdown 相对
链接，但必须保存原生 JSON 和哈希，不得只保存远程 URL。

## 7. 安全和可复现要求

- MinerU Token 仅从构造参数或 `MINERU_API_TOKEN` 读取。
- `allow_cloud=false` 时自动和手动模式都不能调用 MinerU。
- MinerU Zip 解压必须校验路径、单文件大小、总大小和文件数量。
- 每次决策记录 profile、allow_cloud、模型参数和 fallback 顺序。
- 手动模式不允许静默 fallback。
- 重新解析不能再次调用已尝试的同一 parser ID，防止循环。
