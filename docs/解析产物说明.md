# MinerU、OCR 与 VLM 解析产物交付说明

解析组负责 PDF 的 MinerU 解析、图片分类、OCR 和 VLM Caption。每个 PDF 交付一个完整目录；Wiki 组允许做字段映射，但要求 ID 和证据关系可追溯。

## 一、目录

```text
<package_id>/
├── manifest.json
├── items.jsonl
├── chunks.jsonl
├── assets.json
├── visual_evidence.jsonl
├── assets/                 # 原图
└── raw/                    # MinerU 原始 content_list_v2.json
```

文件统一使用 UTF-8；JSONL 每行一个 JSON 对象；路径必须是目录内相对路径。

```json
{
  "schema_version": "mmwiki-0.1",
  "package_id": "demo-document",
  "document": {
    "title": "文档标题",
    "source": {
      "filename": "原始文件.pdf",
      "media_type": "application/pdf",
      "structured_output": "raw/demo_content_list_v2.json"
    }
  },
  "parser": {"name": "mineru", "version": "实际版本"},
  "artifacts": {
    "items": "items.jsonl",
    "chunks": "chunks.jsonl",
    "assets_index": "assets.json",
    "visual_evidence": "visual_evidence.jsonl",
    "assets": "assets/",
    "raw": "raw/"
  }
}
```

## 二、文件格式

`items.jsonl` 保存 MinerU Block。正文和图片使用同一结构；没有内容的字段保留空值。

```json
{"item_id":"item-p0004-b0007","sequence":27,"type":"image","page_start":4,"page_end":4,"bbox":{"values":[100,200,800,700],"coordinate_system":"normalized_1000","origin":"top_left","page_width":595,"page_height":842,"page_unit":"pt"},"breadcrumb":"第三章","content":{"raw_text":"","caption":"PDF 原有图注，没有则为空","search_text":"","semantic":{}},"assets":[{"asset_id":"asset-xxx"}],"metadata":{"visual_type":"chart","contains_text":true},"provenance":{"parser":"mineru","raw_ref":"content_list_v2[3][6]","page":4,"block_index":7},"quality":{"needs_review":false,"review_reasons":[]},"retrieval":{"searchable":true,"exclude":false}}
```

`type` 可使用 `title`、`paragraph`、`list`、`table`、`image`、`chart`、`equation`、`page_header`、`page_footer`、`page_number`。表格同时提供 `content.table.rows/html`，公式提供 `content.equation.latex`。

双方确认：`bbox.values` 为左上角原点的 0–1000 归一化坐标；`page_width/page_height` 保留页面实际尺寸。`content.table.rows` 的正式类型为 `string[][]`（外层为行、内层为列），`html` 原样保留。二维 rows 不表示合并单元格，`rowspan/colspan` 只以 HTML 为准。

`metadata.visual_type` 必须为以下之一：

```text
natural_image      普通插图或照片
chart              图表、流程图、架构图
page_screenshot    页面截图
table_screenshot   表格截图
decorative_image   装饰图片
```

`chunks.jsonl` 负责关联正文、图片和检索文本。一个可检索 Item 对应一个 Chunk 即可；装饰图片可以不生成 Chunk。

```json
{"chunk_id":"chunk-demo-00027","item_ids":["item-p0004-b0007"],"text":"第三章 图表相关正文或图注","breadcrumb":"第三章","modalities":["chart"],"asset_ids":["asset-xxx"],"page_refs":[4],"provenance":{"item_ids":["item-p0004-b0007"],"pages":[4],"context_item_ids":["item-p0004-b0006","item-p0004-b0008"]},"quality":{"needs_review":false}}
```

`assets.json` 是 JSON 数组。每张原图必须真实存在。

```json
[{"asset_id":"asset-xxx","path":"assets/xxx.jpg","media_type":"image/jpeg","sha256":"...","width":1200,"height":800}]
```

`visual_evidence.jsonl` 为每张图片保留两个结果槽位：一条 `image_caption`，一条 `image_ocr`。这不表示两项都必须实际调用模型；需要执行的写 `status=ready`，按策略不执行的仍保留记录并写 `status=skipped`。

```json
{"id":"ve-asset-xxx-image_caption","kind":"image_caption","text":"图片中明确可见的内容","asset_id":"asset-xxx","parent_item_ids":["item-p0004-b0007"],"parent_chunk_ids":["chunk-demo-00027"],"page_refs":[4],"status":"ready","searchable":true,"provenance":{"source":"vlm","model":"qwen3-vl-plus","model_version":null,"prompt_version":"实际提示词版本"},"claims":[{"statement":"图片中有三个模块","provenance":"extracted"}]}
```

```json
{"id":"ve-asset-xxx-image_ocr","kind":"image_ocr","text":"第一行文字\n第二行文字","asset_id":"asset-xxx","parent_item_ids":["item-p0004-b0007"],"parent_chunk_ids":["chunk-demo-00027"],"page_refs":[4],"status":"ready","searchable":true,"provenance":{"source":"ocr","model":"实际 OCR 模型","model_version":null,"task":"text_recognition","prompt_version":"实际提示词或配置版本"},"claims":[]}
```

所有 Asset、Item、Chunk ID 必须能回到对应文件中的记录。`claims` 必须是数组；没有独立结论时写 `[]`。

## 三、处理规则

| 图片类型 | VLM Caption | OCR |
|---|---|---|
| `natural_image` | 必须 | `contains_text=true` 时执行，否则跳过 |
| `chart` | 必须 | 必须 |
| `page_screenshot` | 必须 | 必须 |
| `table_screenshot` | 跳过 | 必须；同时尽量提供结构化表格 |
| `decorative_image` | 跳过 | 跳过 |

- Caption 使用 `qwen3-vl-plus`。每条 OCR/VLM 结果必须记录模型名称、模型版本和提示词版本；服务不提供模型版本时写 `null`。
- VLM 每次输入一张原图，输出严格 JSON：`{"caption":"一段简洁中文","claims":[{"statement":"独立结论","provenance":"extracted|inferred|ambiguous"}]}`。`caption` 只能描述图片中清晰可见的对象、文字和组成，不引用外部知识；没有独立结论时 `claims=[]`。
- OCR 的 `text` 输出图片中全部可辨文字，按阅读顺序保留换行；不总结、不纠错、不补写。
- OCR 与 VLM Caption 分开输出。PDF 原有图注只写入 `items.content.caption`，不得被 VLM Caption 覆盖。
- 每张图片都必须有两个结果槽位。VLM 返回的 `caption` 写入 `image_caption.text`，`claims`原样写入同名字段。未识别时写 `text=""`、`status="ambiguous"` 和 `reason`；调用失败写 `status="error"` 和 `error`；未执行写 `status="skipped"` 和 `reason`；没有结果写 `status="missing"` 和 `reason`。非 `ready` 记录统一写 `searchable=false`。
- 不需要缩略图，必须交付原图。图片通过 `asset_id` 关联原图，通过 `parent_item_ids`、`parent_chunk_ids` 关联正文，通过 `page_refs` 关联页码；装饰图片没有 Chunk 时写 `parent_chunk_ids=[]`。
- 每个 Block 必须提供从 1 开始的真实 PDF 页码、精确 bbox、坐标系、原点和页面宽高；每张图片必须提供实际像素 `width`、`height`。
- Caption 的 `text` 只承载可见事实。独立结论写入 `claims`：原文、表格单元格、OCR 文字和明确可见对象标记为 `extracted`；布局、箭头关系、颜色含义、趋势或跨证据结论标记为 `inferred`；看不清或冲突标记为 `ambiguous`。视觉推断不得标成原文证据。

图片无法识别时仍输出记录，禁止填写猜测内容：

```json
{"kind":"image_caption","text":"","status":"ambiguous","searchable":false,"reason":"图片模糊，无法确认内容"}
```

图片和正文使用稳定 ID 关联：图片 Block 通过 `assets[].asset_id` 指向原图；视觉结果通过 `parent_item_ids` 指向图片 Block、通过 `parent_chunk_ids` 指向检索 Chunk；Chunk 使用 `provenance.context_item_ids` 列出相关正文 Block。

```json
{"asset_id":"asset-xxx","parent_item_ids":["item-p0004-b0007"],"parent_chunk_ids":["chunk-demo-00027"],"page_refs":[4]}
```

```json
{"chunk_id":"chunk-demo-00027","item_ids":["item-p0004-b0007"],"asset_ids":["asset-xxx"],"provenance":{"context_item_ids":["item-p0004-b0006","item-p0004-b0008"]}}
```

无法可靠判断正文与图片关系时，`context_item_ids=[]`，不得仅按距离强行关联。
