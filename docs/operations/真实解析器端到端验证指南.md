# 真实 Docling / MinerU 端到端验证指南

## 目的与边界

本验证直接调用解析器适配器，将真实解析结果归一化为 `ParsedDocument`，再调用独立质量层生成 `QualityPackage`。它不是 mock、fixture 回放或占位结果测试。

入口是 `scripts/run_real_parser_e2e.py`。默认输入为仓库中的表格 PDF：

```text
datasets/shared-dev-v1/files/procurement_table_positive.pdf
```

运行时应使用项目虚拟环境：

```powershell
$python = .\.venv\Scripts\python.exe
```

## 默认安全行为

- 默认 `--mineru-mode local`：只允许本地 MinerU，绝不静默改走云端。
- 默认离线：runner 会设置 `HF_HUB_OFFLINE=1`、`TRANSFORMERS_OFFLINE=1` 与 `HF_DATASETS_OFFLINE=1`；缺少本地模型会明确失败，不会下载或伪造结果。
- 只有显式传入 `--allow-model-download` 时，才允许本地运行时下载缺失模型。
- MinerU 云端 Token 只从运行环境的 `MINERU_API_TOKEN` 读取，不能通过命令行参数或请求参数传入；runner 会在执行证据和解析结果的 adapter warning 中脱敏 Token、常见凭据字段与 URL 签名，并截断过长诊断。
- `DOCUMENT_PARSER_ALLOW_CLOUD=false` 时，云端 MinerU 被服务端策略禁止。

## 真实本地执行

同时验证 Docling、MinerU 和质量层：

```powershell
& $python scripts\run_real_parser_e2e.py `
  datasets\shared-dev-v1\files\procurement_table_positive.pdf `
  --parser all `
  --mineru-mode local `
  --output-dir outputs\e2e\local-smoke
```

Docling 的实际调用路径是 `docling.document_converter.DocumentConverter().convert(...)`。MinerU 的本地适配器会优先使用 `magic_pdf`；当前 CLI 路径为：

```powershell
& $python -m mineru.cli.client --help
```

若 `magic_pdf` 不存在，适配器通过 `python -m mineru.cli.client -p <pdf> -o <dir> -b pipeline` 执行真实 MinerU。预检检查的也是当前虚拟环境中的该 Python module，而非 PATH 上同名命令；`--help` 成功只说明 CLI 可被加载，真正成功仍取决于模型、依赖和硬件是否就绪。

如需在受控环境中首次拉取模型：

```powershell
& $python scripts\run_real_parser_e2e.py `
  datasets\shared-dev-v1\files\procurement_table_positive.pdf `
  --parser all `
  --mineru-mode local `
  --allow-model-download `
  --output-dir outputs\e2e\local-with-model-download
```

## MinerU 云端执行

云端模式必须由运行环境配置 Token，且服务端云端策略允许：

```powershell
$env:MINERU_API_TOKEN = '<server-owned-token>'
& $python scripts\run_real_parser_e2e.py `
  datasets\shared-dev-v1\files\procurement_table_positive.pdf `
  --parser mineru `
  --mineru-mode cloud `
  --output-dir outputs\e2e\mineru-cloud
```

不要把 Token 写入脚本、提交到仓库或作为 runner 参数传入。未配置 Token 时，云端模式写出 `skipped` 证据并以退出码 `2` 结束；它不会调用适配器，也不会输出伪成功。需要将明确跳过作为可接受的可用性检查时，显式附加 `--allow-skips`，但这不代表 MinerU 已经真实执行。

## 成功判定和产物

每个解析器在 `<output>/<parser>/` 下写入 `execution-evidence.json`。只有实际执行证据满足以下条件，结果才会标记为 `succeeded` 并运行质量层：

| 解析器 | 必须存在的真实证据 |
| --- | --- |
| Docling | `native/docling_document.json` 和 `native/full.md` |
| MinerU | `native/mineru_result.json`、云端/CLI/magic-pdf 完成标记、非空归一化 Markdown、至少一个非空原始 Markdown sidecar，以及至少一个可解析且非空的 `content_list*.json` 或 `*_middle.json` sidecar（嵌套目录允许） |

真实执行成功后还会生成：

```text
<output>/<parser>/parsed_document.json
<output>/<parser>/native-artifacts.json
<output>/<parser>/quality_package.json
<output>/run-summary.json
```

`quality_package.json` 说明解析结果已经进入质量层；其质量状态可以是 `pass`、`pass_with_warnings`、`manual_review_required` 或 `reparse_required`，这与“解析器是否真的运行过”是两件独立的事。

任何 placeholder、适配器异常、缺失 native sidecar、无效 MinerU 结构化 sidecar 或缺失 MinerU 完成标记都会得到 `failed`，退出码为 `1`，并且不会生成质量包。MinerU 已实际启动但失败时会抛出带安全 `failure_kind`、`retryable` 与 `safe_message` 的解析执行错误；runner 会把前两项写入执行证据，而不会落盘原始 CLI stderr 或云端响应体。为便于诊断，失败记录仍可能包含 `parsed_document.json` 与 `native-artifacts.json`；只有 `execution-evidence.json` 的 `outcome=succeeded` 且存在 `quality_package.json` 才表示真实端到端成功。

| 退出码 | 含义 |
| --- | --- |
| `0` | 所有请求的解析器真实成功；或显式 `--allow-skips` 后只有成功/跳过 |
| `1` | 至少一个解析器实际失败，或返回了不被认可的占位结果 |
| `2` | 至少一个解析器被显式跳过，且未传 `--allow-skips` |

先只检查环境和计划、完全不调用模型时，可以运行：

```powershell
& $python scripts\run_real_parser_e2e.py --dry-run --parser all `
  --output-dir outputs\e2e\dry-run-preflight
```

`--dry-run` 的记录状态为 `planned`，它不是解析成功。

## Pytest 入口

默认测试不会下载模型，也不会调用云端：

```powershell
& $python -m pytest tests\e2e -m e2e -q
```

它会显示为 `skipped`。在已准备好模型/授权的执行环境中，显式开启真实验证：

```powershell
$env:RUN_REAL_PARSER_E2E = '1'
$env:REAL_PARSER_E2E_PARSER = 'all'
$env:REAL_PARSER_E2E_MINERU_MODE = 'local'
$env:REAL_PARSER_E2E_ALLOW_MODEL_DOWNLOAD = '0'
& $python -m pytest tests\e2e -m e2e -q
```

可选环境变量：

| 变量 | 默认值 | 作用 |
| --- | --- | --- |
| `REAL_PARSER_E2E_SOURCE` | 内置表格 PDF | 覆盖输入 PDF（相对路径相对仓库根目录） |
| `REAL_PARSER_E2E_PARSER` | `all` | `all`、`docling` 或 `mineru` |
| `REAL_PARSER_E2E_MINERU_MODE` | `local` | `local`、`cloud` 或 `auto` |
| `REAL_PARSER_E2E_ALLOW_MODEL_DOWNLOAD` | `0` | 显式允许本地 runtime 下载模型；本地 runtime 已安装但模型缺失会是 `failed`，而非 `skipped` |
| `REAL_PARSER_E2E_ALLOW_SKIPS` | `0` | 仅用于可用性检查；不证明被跳过的解析器已经运行 |
| `REAL_PARSER_E2E_OUTPUT_DIR` | `outputs/e2e/pytest-<pid>-<time>` | 覆盖 pytest 调用 runner 的证据输出目录 |
| `REAL_PARSER_E2E_TIMEOUT_SECONDS` | `1800` | 子进程超时秒数 |

在默认严格模式下，任何 `failed` 或 `skipped` 都会让 pytest 失败，从而避免把“没有 Token / 没有模型”误报为真实端到端通过。
