# 杨欣川多模态产物 → ParsedDocument 对齐说明

## 结论

朱侧 `ParsedDocument` 是解析领域的唯一输出协议，杨侧是多模态增强下游。朱侧基础设施反腐层将 ParsedDocument 确定性发布为杨侧现有加载器可读的 `mmwiki-0.1` 包；领域层不依赖 mmwiki，杨侧也无需理解不同解析器的私有结果。

## 身份映射

| ParsedDocument | mmwiki-0.1 | 规则 |
|---|---|---|
| `document_id/filename` | `package_id/document.source.filename` | package ID 安全化，原文件名不丢失 |
| `provenance.parser_id/version` | `parser.name/version` | 必须是真实值，并标记来源为 ParsedDocument |
| `blocks[].source_block_id` | `item_id` | 优先保留解析器稳定 ID；缺失时使用 block UUID |
| `blocks[].order_index` | `sequence` | 统一为从 1 开始的阅读顺序 |
| `anchor.page_number/page_end` | `page_start/page_end` | PDF 页码真实且从 1 开始 |
| `anchor.bbox/...` | bbox 对象 | 输出统一为 `normalized_1000/top_left` |
| `anchor.section_path` | `breadcrumb` | 多级路径用 ` > ` 连接 |
| `DocumentAsset.asset_id` | `assets[].asset_id` | 跨 Item/Chunk/Evidence 的稳定外键 |
| `retrieval_chunks[]` | `chunks.jsonl` | 保留 item、asset、page、context 关系 |
| `tables[]` | `items.content.table` | 输出 `string[][] rows + html`，不猜测 span |

## 类型映射

`title→heading`、`chart→image(native_type=chart)`、`equation→formula`、`page_header→header`、`page_footer→footer`；其他同名类型直接映射。`metadata.visual_type` 原样保留，允许值严格采用杨侧五种枚举。

## 已采纳的确定规则

- 不需要缩略图，交付原图。
- natural_image/chart/page_screenshot 必须 Caption；table_screenshot/decorative_image 跳过。
- chart/page_screenshot/table_screenshot 必须 OCR；natural_image 按 contains_text；decorative_image 跳过。
- 每个图片固定有 image_caption 和 image_ocr 两个 VisualEvidence 槽位。
- 非 ready 必须 `searchable=false`；skipped/ambiguous/missing 必须有 reason；error 必须有 error。
- ready 必须记录 source、model、model_version（允许 null）、prompt_version。
- PDF Item 必须有真实 page、bbox、页面尺寸、坐标系、原点和单位。
- 原始图注、OCR、VLM Caption 不互相覆盖。
- claims 只允许 extracted/inferred/ambiguous；视觉推断不能冒充原文证据。
- 无法可靠关联正文时 `context_item_ids=[]`。

## 已确认的接口细节

1. `bbox.values` 固定为 `[left, top, right, bottom]`，左上角为原点，每个值均为 0–1000 归一化坐标。实仓 10 个包的 bbox 均未携带 `page_width/page_height`，因此这两个字段按可选处理：缺失时保留归一化定位并将物理坐标能力标为 partial；有值时它们表示页面实际尺寸（单位由 `page_unit` 指定），换算公式为 `x/1000*page_width`、`y/1000*page_height`。禁止把归一化值当作 pt。
2. `items.content.table.rows` 正式 Schema 为 `string[][]`：外层按行，内层按列，单元格值统一为字符串；同时保留 `content.table.html`。`rows` 本身不表达 `rowspan/colspan`，合并单元格等结构以 HTML 为准；适配器不得猜测或伪造 `TableCell` span。

```json
{
  "content": {
    "table": {
      "rows": [
        ["季度", "销售额（万元）", "同比"],
        ["第一季度", "120", "10%"],
        ["第二季度", "150", "15%"]
      ],
      "html": "<table>...</table>"
    }
  }
}
```

## Gate 分工

朱侧保证 ParsedDocument 的 ID 外键、路径、文件、哈希和 PDF 定位字段，并由 `MmwikiPackageAdapter` 完成出站映射；杨侧消费兼容包并完成 OCR、Caption 等多模态增强；叶侧质量层决定语义质量与准入状态。

## 联调证据

- 杨组仓库现有 10 个 `mmwiki-0.1` 包均通过其自带 `validate_package`。
- 真实数据包含 5,121 个 `normalized_1000/top_left` bbox 和 197 个 `rows + html` 表格。
- 朱侧 `ParsedDocument` 经 `MmwikiPackageAdapter` 生成包后，已通过杨组真实 `mmwiki.contracts.load_package()` 加载测试。
