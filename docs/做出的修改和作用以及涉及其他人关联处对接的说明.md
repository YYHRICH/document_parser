# 做出的修改和作用以及涉及其他人关联处对接的说明

## 1. 本次修改

### 路由代码

- 新增解析器能力注册表，注册 `docling`、`anydoc`、`mineru` 和内部 `passthrough`。
- 新增 `local_first`、`quality_first` 两套策略。
- PDF 按当前决策固定优先 MinerU。
- 新增 `allow_cloud` 开关；禁用后所有 MinerU 候选都会被排除并记录原因。
- 新增自动模式、手动指定、显式 fallback 和模型不可用处理。
- 新增 `ReparseRecommendation` 校验，阻止同一解析器循环重跑。
- 为三个 Adapter 生成可复现的 `parser_options`，但不执行解析器。

### 工程和配置

- 新增 `.env.example`，不包含真实 Token。
- 新增 `pyproject.toml`，解决下载目录名为 `document_parser-main` 时无法稳定导入的问题。
- 新增 Docling 可选依赖清单；AnyDoc 因为是 npm 工具，仍需独立安装。
- 新增独立路由 CLI `document-parser-route`。
- 新增共享 12 文件的路由期望 `annotations/routing.jsonl`。
- 新增路由单元测试，不依赖真实模型和网络。

### 明确未修改

- 没有修改 `RoutingDecision 1.0`、`ParsedDocument 2.2`、`QualityPackage 1.0` 字段。
- 没有把 Token 写进仓库、决策或测试。
- 没有实现 Docling、AnyDoc、MinerU Adapter、Web 或质量算法。
- 没有重复运行已经完成的 50 张图片测试。

## 2. 与朱的对接

朱负责消费 `RoutingDecision` 并执行 Adapter。需要完成：

1. Gateway 使用 `ModelRouter.route_request(request)` 获取决策。
2. 建立 parser ID 到 Adapter 的稳定映射。
3. 对 `fallback_parser_ids` 逐个执行，并把失败原因写入 `fallback_history`。
4. 严格校验 `parser_options`，未知或不支持的参数必须报错。
5. 将原生产物映射为 `ParsedDocument`，不能把私有对象直接传给质量层。
6. 统一落盘 `document.md + images/ + parsed_document.json + native/`。

Docling Adapter 应消费：`output_formats`、`image_export_mode`、`table_mode`、`ocr`、
`ocr_engine`、`ocr_mode` 和语言。当前前期脚本关闭图片生成并使用 placeholder，不能直接
作为正式 Adapter。

MinerU Adapter 应消费精准 API 参数，Token 从服务配置获取，不能从
`parser_options` 获取。必须下载完整 Zip，而不是只下载 `full.md`。轮询、超时、错误码、
安全解压、CDN 下载失败和 Token 过期都要形成明确错误。

AnyDoc Adapter 应在受控子进程中执行，设置超时并捕获退出码。旧 Office 原件必须保留。

## 3. 与叶的对接

叶只读取 `ParsedDocument 2.2`。路由层向其保证：

- `routing_decision.selected_parser_id` 表示计划模型；
- `provenance.parser_id` 由朱填写实际成功模型；
- Docling/MinerU 参数可用于复现解析来源；
- 禁止云端和模型不可用原因可以回溯。

叶返回 `ReparseRecommendation` 时应提供不同于已尝试解析器的 `parser_id`、原因和必要
参数。路由器会再次检查格式、可用性和云端限制。质量层不得直接调用模型。

## 4. 与公共契约的关系

本次没有改变公共字段，因此朱、叶现有 fixture 仍兼容。以后若希望在公共协议中新增
`route_profile` 或 `allow_cloud` 顶层字段，需要三人共同评审并同步模型、样例、测试和
Spec。当前版本把它们放在 `ParseRequest.options` 和 `RoutingDecision.parser_options`，
避免破坏冻结契约。

## 5. 仍需其他同学实现或确认的事项

- Gateway 当前仍固定调用 MarkItDown，需要朱完成真实编排。
- AnyDoc、Docling、MinerU 的正常化器和原生产物归档尚未实现。
- `comparison_parser_ids` 只是质量优先模式的执行请求，双解析评分和择优应由编排/质量层实现。
- MinerU Token 90 天到期，需要部署侧监控和更换，不能依赖写死的个人 Token。
- 当前共享 manifest 中少量历史 `candidate_parsers` 仍使用 `ocr` 表示 OCR 路径；正式
  执行以 `annotations/routing.jsonl` 和本路由器的 `docling` ID 为准，合并前建议三人共同
  将 manifest 术语更新为 Docling + RapidOCR。
