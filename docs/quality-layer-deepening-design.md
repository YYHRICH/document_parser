# 质量层深化设计：结构表格、证据与可验证交付

## 1. 设计背景

交接文档的回放结果表明，解析层不能只把表格当作一段 Markdown 文本。对于多级表头、合并单元格、跨页续表、超大表格和筛选视图，Wiki 需要同时获得可读内容、可查询结构和可追溯的源单元格证据。

本设计把一条表格记录明确为：

> 行头路径 × 列路径 × 单元格值 × 源坐标

其中“行头路径”和“列路径”不能只依赖一个字符串键；源坐标也不能只依赖页面框。Excel 的工作表、单元格地址、筛选范围、隐藏行和公式显示值都属于交付语义的一部分。

交接文档还确认了一个必须保留的区别：`toMarkdown` 通常表示全量内容，而 `toDocument` 可能表示 AutoFilter 后的可见视图。质量层不能擅自把两者混成同一份数据，必须把视图范围写清楚。

## 2. 设计目标与边界

质量层负责：

- 检查输入身份、块引用、表格引用和源定位是否闭合；
- 把表格转换成稳定的网格、表头路径、行头路径和单元格证据；
- 进行确定性的格式和结构修复；
- 重新构建并复检修复结果；
- 输出 Markdown、结构化表格记录、Wiki 查询绑定和质量状态。

质量层不负责：

- 与原始 Excel、PDF 或图片逐字逐格比对的最终评测；
- 猜测缺失的事实、标题、隐藏行、公式结果或跨页关系；
- 把业务语义改写成更“通顺”的文字；
- 用大模型替代可复现的结构规则。

源文件对比、模型间能力比较和最终准确率属于数据评测层；Wiki 只消费已经通过质量门的三个交付文件。

## 3. 深化后的执行链路

```text
ParsedDocument
  -> 输入身份与引用完整性校验
  -> 表格结构图构建（网格、span、表头、行头、可见性）
  -> 结构记录生成（行路径 × 列路径 × 值 × 单元格证据）
  -> Markdown / 结构网格 / 来源证据一致性检查
  -> 跨页续表与列漂移诊断
  -> 确定性白名单修复
  -> 修复后重新构建与复检
  -> 能力状态、覆盖率指标和质量门
  -> optimized.md + structure.json + quality_issues.json
```

结构化表格和绑定必须支持双向定位：

- 从结构记录定位到 `table_id`、`cell_id`、工作表和单元格地址；
- 从 Markdown 行或 Wiki 查询结果回指到对应的结构记录和源证据。

## 4. 统一输入契约需要深化的部分

### 4.1 统一源定位器

现有 `SourceLocator` 需要从“页码和框”扩展为可组合定位器。推荐字段如下：

```json
{
  "container": "sheet",
  "container_name": "拟纳管单位",
  "page_number": null,
  "cell_ref": "D12",
  "range_ref": "A8:K630",
  "bbox": null,
  "granularity": "cell",
  "provenance": "xlsx:workbook.xlsx"
}
```

不同来源只填适用字段：PDF 使用页码和 `bbox`，Excel 使用工作表、单元格地址和范围，演示文稿使用幻灯片编号。质量层不应为了统一而伪造不存在的坐标。

### 4.2 `ParsedTable` 必须表达表格视图

`ParsedTable` 除了 Markdown、HTML 和行列数，还应包含：

- `source_container`：文件、工作表或页面；
- `dimensions`：源范围、逻辑行列数、物理网格行列数；
- `header_rows`、`row_header_columns`；
- `cells`：包含合并关系和单元格角色的完整单元格集合；
- `view_scope`：`all_rows`、`visible_rows` 或 `unknown`；
- `source_has_filter`、`source_row_count`、`emitted_row_count`、`hidden_row_count`；
- `representation`：原始 HTML、渲染 Markdown、结构网格之间的关系。

例如，AutoFilter 只输出 8 行时，质量层应记录“源表 622 行、输出可见视图 8 行”，不能报告为“内容缺失”或默默补齐。

### 4.3 `TableCell` 的目标字段

建议把 `TableCell` 深化为以下语义：

```json
{
  "cell_id": "tbl-001-cell-r12-c04",
  "text": "28.2%",
  "raw_value": 0.282,
  "display_value": "28.2%",
  "normalized_value": "28.2%",
  "value_type": "percentage",
  "formula": null,
  "start_row": 12,
  "start_col": 4,
  "row_span": 1,
  "col_span": 1,
  "roles": ["value"],
  "visible": true,
  "source_locator": {
    "container": "sheet",
    "container_name": "经营指标",
    "cell_ref": "D12",
    "granularity": "cell"
  }
}
```

`raw_value`、`display_value` 和 `normalized_value` 必须分开。质量层可以清理空白和控制字符，但不能把日期、百分比、金额或公式结果强行改成另一种事实。

## 5. 规范表格与绑定 JSON 设计

### 5.1 在 `canonical_document` 中增加完整表格集合

质量包已增加 `canonical_document.tables[]`，作为绑定可引用的规范表格网格：

```json
{
  "table_id": "tbl-001",
  "block_id": "block-017",
  "source_locator": {
    "source_block_id": "anydoc-table-block-0000",
    "container": "sheet",
    "container_name": "拟纳管单位",
    "range_ref": "A8:K630",
    "provenance_status": "verified"
  },
  "num_rows": 8,
  "num_cols": 11,
  "header_row_indices": [0, 1],
  "title_row_indices": [],
  "header_state": "verified",
  "view_scope": "visible_rows",
  "source_has_filter": true,
  "source_row_count": 622,
  "emitted_row_count": 8,
  "hidden_row_count": 614,
  "cells": [
    {
      "cell_id": "tbl-001:r2c3",
      "start_row": 12,
      "start_col": 4,
      "row_span": 1,
      "col_span": 1,
      "text": "是",
      "raw_value": "是",
      "display_value": "是",
      "source_anchor": {
        "container": "sheet",
        "container_name": "拟纳管单位",
        "table_cell": "r12c4"
      }
    }
  ],
  "grid": [
    [{"kind": "origin", "cell_id": "tbl-001:r0c0"}],
    [{"kind": "covered", "origin_cell_id": "tbl-001:r0c0"}]
  ]
}
```

这份表格集合是结构真相；它不能只保存展开后的 Markdown 文本。合并单元格应保留 `row_span`、`col_span`，被覆盖的位置不能伪造为新的源单元格。

### 5.2 `table_bindings` 使用路径和单元格引用

`row_key` 保留为便于索引的展示键；`row_path` 和组成路径的单元格引用负责表达可逆的多级行头：

```json
{
  "binding_id": "bind-001",
  "table_id": "tbl-001",
  "block_id": "block-017",
  "row_path": ["华北区域", "一线单位"],
  "column_path": ["人员", "专职单位"],
  "row_cell_ids": ["tbl-001-cell-r12-c01", "tbl-001-cell-r12-c02"],
  "column_cell_ids": ["tbl-001-cell-r08-c03", "tbl-001-cell-r09-c04"],
  "value_cell_id": "tbl-001-cell-r12-c04",
  "value": "是",
  "source_locator": {
    "container_name": "拟纳管单位",
    "cell_ref": "D12",
    "granularity": "cell"
  },
  "status": "verified",
  "evidence": {
    "row_path_source": "explicit_row_headers",
    "column_path_source": "multi_level_headers",
    "value_source": "cell_value"
  }
}
```

### 5.3 三种表示的职责分离

- `optimized.md`：面向阅读和检索，保持源顺序，使用可读的填充表格；
- `canonical_document.tables[]`：面向结构查询，保存网格、span、原始/显示值和源坐标；
- `table_bindings`：面向 Wiki 问答的轻量索引，只保存路径和单元格引用，不重复整张表。

Wiki 在回答时可以由 `row_path`、`column_path` 和 `value_cell_id` 生成完整上下文；评测层则用 `source_locator` 回到原始数据做对比。质量层不把评测结论写成结构事实。

## 6. 质量规则深化

### 6.1 引用闭合

- 每个表格必须引用存在的内容块；
- 每个 `cell_id` 只能属于一个表格；
- 每个绑定的 `table_id`、`block_id`、行列单元格引用和值单元格引用都必须存在；
- 源定位器若声明 `cell_ref`，必须满足表格范围和行列边界；
- 发现悬空引用时，质量门拒绝该文档的结构交付。

### 6.2 网格、合并和占位

- 检查 `row_span`、`col_span` 是否越界；
- 检查合并区域是否重叠；
- 区分“合并单元格覆盖位置”和“真实空单元格”；
- 检查结构网格是否存在无法解释的缺口；
- 只在存在明确源证据时生成填充值，禁止把合并值复制成新的源单元格。

### 6.3 表头、行路径和空值

- 保留多级 `column_path`，不把层级标题简单拼成一个不可逆字符串；
- 显式行头优先于推断行头；
- 行路径重复时保留绑定并标记歧义，不覆盖已有记录；
- 空字符串、空单元格、合并覆盖和缺失值必须使用不同状态；
- 每条绑定都要能回溯到组成行路径和列路径的单元格。

### 6.4 表示一致性

- HTML 转 Markdown 只做白名单转换：表格标签、段落换行、实体、空白和安全链接；
- 记录原始 HTML、规范表格和 Markdown 之间的表示差异；
- 不把 HTML 中的公式、图片占位符或日期显示值改写成猜测结果；
- `&lt;` 等实体解码、换行折叠和分隔线补齐必须是可复现规则。

### 6.5 可见性、跨页和大表

- AutoFilter 的全量行、可见行和隐藏行必须分别计数；
- 跨页续表先记录关系和列漂移诊断，不直接物理合并；
- 大表使用稳定排序和流式计数，不能为了性能静默截断；
- 发现截断、范围不完整或列数漂移时，应降级能力状态并保留原始页/表。

## 7. 允许修复与禁止修复

允许的确定性修复包括：

- 去除首尾空白、统一换行和清理不可见控制字符；
- 把安全的表格 HTML 转成 Markdown；
- 补齐 Markdown 分隔线和转义字符；
- 为已有源单元格生成稳定的 `cell_id`；
- 根据已存在的表头和行头生成路径索引；
- 补全可证明的块引用和来源粒度标记。

禁止的自动修复包括：

- 把合并单元格复制成多个“新事实”；
- 猜测缺失表头、隐藏行、公式、日期或业务单位；
- 未有明确证据时自动合并跨页表格；
- 用表格框或页面框冒充缺失的单元格框；
- 让大模型改写原文事实、数字或实体名称。

## 8. 质量指标与质量门

质量包应至少统计：表格数、源/输出行数、列数、单元格数、合并区域数、可见/隐藏行数、筛选状态、绑定数、绑定覆盖率、源定位覆盖率、Markdown 表格匹配率、跨页续表数、列漂移数、表示损失数、公式差异数和截断状态。

推荐指标：

```text
结构网格覆盖率 = 可解释的物理网格位置 / 物理网格位置总数
绑定覆盖率 = 有完整行路径、列路径和值单元格引用的绑定数 / 绑定总数
源定位覆盖率 = 带有效源定位的单元格数 / 规范表格单元格数
```

质量门建议：

| 情况 | 处理 |
|---|---|
| 悬空引用、越界 span、严重占用冲突 | 拒绝结构交付 |
| 单表网格无法解释 | 该表降级并保留原始表示 |
| 行路径或列路径由规则推断 | 允许交付，标记警告 |
| 只有表级定位，没有单元格定位 | 允许 Markdown，结构能力标记受限 |
| AutoFilter 视图 | 正常交付，但必须声明视图范围 |
| 跨页续表关系不确定 | 保留分表，标记待评估 |
| 检测到截断 | 拒绝该表的完整性声明 |
| 只有 Markdown、没有结构绑定 | 只能声明阅读能力，不能声明表格问答能力 |

## 9. 质量层与数据评测层的边界

质量层验证“自身是否闭合、可定位、可复现”；数据评测层验证“是否忠实于原始数据”。二者不能混写：

- 评测层把原始 Excel 网格、原始 PDF 文本或人工真值作为基准；
- 评测层可以对日期格式、实体空格、零宽字符、控制字符和公式显示差异做显式归一化；
- AutoFilter 需要分别建立全量基线和可见视图基线；
- 质量层只输出 `view_scope`、`source_locator` 和表示差异，不能把对比结果伪装成解析事实。

必要时可增加 `SourceGridEvidence`，但它应是评测输入或评测产物，不应污染 Wiki 的核心查询包。

## 10. 大表和性能设计

以 22503×11 的 MOA-IT 制度和 22505×11 的批量导入表为基准：

- 超过 5 万个结构单元格后，不再创建内存 `BindingCandidate` 列表；
- 大表的单元格、来源坐标和字段绑定流式写入 `table_index.sqlite3`；
- `structure.json` 只保留表级描述和索引契约，不展开大表的 `cells`、`grid`、`table_bindings`；
- 数据库按表内行列、工作表+A1 坐标、表+行键建立索引，并在环境支持时建立单元格全文索引；
- 输出前后都检查记录数量，不允许静默截断；
- 测试夹具覆盖超大表、多级表头、连续合并、筛选视图和 DISPIMG 公式。

## 11. 实施顺序

1. 先更新统一输入契约：源定位器、表格视图和 `TableCell` 字段。
2. 在质量包中增加规范 `tables[]`，再把绑定改为路径加单元格引用。
3. 实现引用闭合、网格/span、表头路径、可见性和表示一致性规则。
4. 下游固定消费三个基础文件；大表增加 `table_index.sqlite3`。
5. 用交接数据集建立回归集：MOA-IT 制度、批量导入、大音、投标评分标准、拟纳管单位、副矿长、DISPIMG 以及 PDF 表格。

## 12. 最终设计判断

深化后的质量层输出不只是“修过的 Markdown”，而是：

- 可阅读的 `optimized.md`；
- `structure.json` 中可查询的普通表结构，以及大表的 SQLite 索引描述；
- `table_index.sqlite3` 中的大表单元格、字段绑定、来源坐标和查询索引；
- `quality_issues.json` 中可复检的质量状态、修复记录、人工复核项和警告；
- 工作表/页面/单元格级来源证据；
- AutoFilter 和跨页语义。

因此需要直接调整六点：把结构表格变成质量层的一等产物；把单一 `row_key` 改为 `row_path`；把 `TableCell` 扩展为带原始值、显示值、公式和定位的实体；显式表达全量/可见视图；把源对比留给评测层；大表改用流式 SQLite 索引并保留无截断计数。

下游固定接收三个基础文件：`optimized.md` 负责可读正文，`structure.json` 承载普通表结构和大表索引说明，`quality_issues.json` 承载质量状态、修复记录和人工复核项。存在大表时追加 `table_index.sqlite3`，承载完整单元格和字段绑定。

## 13. 交接文档对当前质量层的直接指导与落地状态

交接文档中的结论需要这样落到质量层，而不是简单复制实验统计：

| 交接结论 | 对质量层的要求 | 当前实现情况 |
|---|---|---|
| Markdown 全量内容可保留 | `optimized.md` 继续作为全文交付，不做事实改写 | 已保留；表格 Markdown 使用 anchor-copy 作为可读表示 |
| 合并单元格和 span 可保留 | 质量包必须保留物理单元格、span 和覆盖关系 | 已落地 `tables[].cells/grid`，covered 槽位回指 origin |
| 表格记录由行头路径、列路径和值组成 | 绑定不能只保存一个 `row_key` | 已增加 `row_path` 及三组 cell ID 引用 |
| AutoFilter 输出的是可见视图 | 必须声明全量行、可见行和隐藏行，不能把视图差异当解析错误 | Excel 预检已填充视图和三类行数 |
| 跨页续表不能盲目拼接 | 保留续表关系和列漂移诊断，必要时分表交付 | 继续保留关系规则，规范表格作为关系端点 |
| 超大表需要完整计数 | 记录源行数、输出行数、绑定数和截断状态 | 已加入表格、单元格、合并锚点、网格、视图和嵌套计数；截断检测仍需解析器证据 |
| 结构记录能回到源单元格 | 每条绑定要能定位到值单元格、行路径单元格和列路径单元格 | 已落地稳定 `cell_id` 与引用闭环测试 |

由此，质量层深化的核心不是增加更多“文本润色”规则，而是把结构、来源和视图语义补齐。

## 14. 已落地的六个改造面

### 14.1 统一输入模型

`ParsedTable`、`TableCell` 和 `CanonicalSourceLocator` 已补充源容器、工作表/页面、范围、原始值、显示值、公式、角色、可见性和稳定 `cell_id`。没有原生单元格坐标时仍只声明表级或逻辑网格级证据，不伪造 A1 地址和 bbox。

### 14.2 规范表格输出

`CanonicalDocument` 已增加规范表格集合，不再只输出 `table_bindings`。每张表保存：

- 源容器和源范围；
- 逻辑行列数与物理网格行列数；
- 完整单元格集合及 span；
- 表头行、行头列；
- `view_scope` 和筛选统计；
- 表格表示差异和能力状态。

这样 Wiki 才能在不重新解析 Markdown 的情况下处理复杂表格。

### 14.3 绑定结构

`BindingCandidate` 和 `TableFieldBinding` 已增加：

- `row_cell_ids`；
- `column_cell_ids`；
- `value_cell_id`；
- 绑定来源是显式、推断还是不可用；
- 空值、覆盖位置和缺失值的区别。

适配器未提供原生 ID 时，统一层按 `table_id:r{row}c{col}` 生成确定性 ID；规范表格和绑定共享同一身份算法，测试会检查引用不悬空。

### 14.4 规则与质量门

在已有网格、表头、跨页规则之外，已增加或加强：

1. 表格、块、单元格、绑定和来源之间的引用闭合；
2. span 越界、占用冲突、数据区空洞和合并覆盖状态；
3. 全量/可见/隐藏行计数与筛选范围一致；
4. 绑定覆盖率、源定位覆盖率、结构网格覆盖率和截断状态。

悬空引用、越界 span、严重占用冲突和检测到的截断应阻止结构交付；路径推断、表级定位和跨页关系不确定则交付但明确降级能力状态。

### 14.5 修复策略

HTML 表格转 Markdown 仍然保留，但它只负责生成可读正文和同步表格块。规范表格应从输入单元格结构构建，不能从 Markdown 反向猜结构。对于 Excel 中原始字符串已经明确保存、但解析结果丢失的单元格内换行，可以用 `raw_value` 做确定性恢复；修复必须同时更新单元格、规范表格 Markdown、表格 block 和全文，任何一处不能安全定位就拒绝修复。修复层可以清理空白、实体和分隔线，但不能补写隐藏行、复制合并事实、猜测公式结果或把表格框冒充单元格框。

### 14.6 回归与性能

交接文档中的 11 个 Excel 文件、17 个工作表和两张 22500 行级大表应成为质量层回归夹具。每次运行至少验证：

- 表格和单元格数量没有静默减少；
- 合并区域和覆盖关系保持一致；
- AutoFilter 的源行/可见行/隐藏行统计明确；
- 结构记录可以回指源单元格；
- 同一输入重复运行时 ID、排序和指标稳定；
- 复杂表格不会因为生成绑定而复制整张单元格证据。

## 15. 本轮实现结果与剩余边界

已经完成：

1. AnyDoc 直接调用 `toDocument`，把 origin/covered、span、`headerRows`、工作表 heading 和真嵌套表映射到统一结构。
2. Excel 输入预检使用 `openpyxl/xlrd` 补充工作表范围、筛选状态、隐藏行、源/输出行数、合并区域计数，并在行列可安全对齐时给每个单元格补充 A1 坐标、原始值、值类型和公式。
3. 规范输出加入 `tables[]`；绑定加入行路径、列路径和值单元格引用，并支持合并行头在 covered 行上的上下文继承。
4. 质量规则检查网格引用、全量/可见/隐藏行对账、源单元格定位、嵌套父子引用、伪嵌套文本，以及文档 Markdown、表格 block、表格 Markdown 和逻辑网格之间的表示一致性；无法证明的情况进入人工复核。
5. 最终结构 JSON 检查 block、table、cell、binding、父子表和 relation 的引用闭合；构建时不再把“需要人工复核”的关系悄悄降级成普通推断。
6. 问题统计按“尚未修复、需要人工复核、需要重新解析、拒绝”分别计数，同一问题事实不会因多个规则入口重复计数。

仍保留的能力边界：

- Excel 行列与 AnyDoc 网格无法安全对齐时，不生成伪 `cell_ref`，而是记录 `table_source_mapping` 人工复核项；
- 伪嵌套表缺少列边界，不能无损自动拆成子表，只保留文本并标记人工复核；
- 大模型不参与确定性网格修复；
- 跨页表自动合并、公式语义验证和原文件逐格准确率仍分别属于后续规则或数据评测层。
